Alexandrie renders Markdown directly in documents. You can use the usual Markdown syntax and a few extensions designed for notes, technical documentation, and collaborative work.

## Text and headings

Use one to six `#` characters for headings. Headings receive an automatic anchor, so they can be linked from the document.

```md
# Main title

## Section

### Subsection
```

Inline formatting can be combined in the same paragraph:

```md
**Bold text** or **underlined text**
_Italic text_ or _italic text_
~~Strikethrough~~
==Highlighted text==
^superscript^ and ~subscript~
```

In Alexandrie, `__text__` is rendered as underlined text rather than bold text. Use `**text**` when you need bold text.

## Links and images

Create external links with the standard Markdown form:

```md
[Alexandrie on GitHub](https://github.com/Smaug6739/Alexandrie)
```

Images use the same form with an exclamation mark:

```md
![Alexandrie logo](/Logo/Alexandrie-logo-light.svg)
```

You can control the displayed size by adding dimensions after the alternative text:

```md
![A square image | 200x200](image.png)
![A wide image | 640x360](image.png)
![A fixed-width image | 320](image.png)
![A fixed-height image | x240](image.png)
```

The width and height are expressed in pixels. `640x` sets only the width, while `x240` sets only the height. SVG images are embedded as objects so that their own colours can be preserved.

## Quotes and separators

Use `>` for a quotation. Quote markers can be nested.

```md
> A short quotation.
>
> — Author
```

Horizontal rules separate large sections:

```md
---
```

The `***` form is also supported.

## Lists and task lists

Unordered and ordered lists can be nested by indenting the child list.

```md
- First item
- Second item
  - Nested item
  - Another nested item

1. Prepare the document
2. Review the changes
3. Publish it
```

Task items use a checkbox marker at the beginning of the item:

```md
- [ ] To do
- [x] Completed
- [x] Also completed
```

Rendered task checkboxes are interactive. They are useful for short checklists; use a dedicated workflow or a structured document when the list needs ownership, dates, or history.

## Tables

Tables use the standard pipe syntax. The second row separates the header from the body.

```md
| Item          | Status      | Owner |
| ------------- | ----------- | ----- |
| Documentation | In progress | Alex  |
| Release notes | Done        | Sam   |
```

Keep the separator row in place even when the columns are not aligned with spaces.

## Code

Use single backticks for inline code:

```md
Run `make dev` from the project directory.
```

Use fenced blocks for multi-line code. Add a language name after the opening fence to enable syntax highlighting.

````md
```ts
const documentTitle = "A useful note";
console.log(documentTitle);
```
````

Code blocks include a copy button in the rendered document. Fences with no language are also valid:

````md
```
Plain text or configuration
```
````

## HTML and escaping

HTML is enabled in the Markdown renderer. This can be useful for small presentation details, but only use trusted HTML and keep it readable.

```md
<span style="color: red">Important</span>
```

The renderer also supports automatic links for URLs written directly in the text. Use Markdown links when you need a custom label.
