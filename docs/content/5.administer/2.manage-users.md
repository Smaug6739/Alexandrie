The user management page is where administrators handle account creation for the instance. It is the recommended place to onboard people without requiring them to create their own accounts manually.

## Accessing user management

From the admin dashboard, open the user management section. This view lets you:

- create individual accounts;
- import accounts from CSV;
- review the current user list;
- prepare onboarding flows for teams and workspaces.

## Create a single user

The manual creation form asks for:

- username;
- email;
- first name;
- last name;
- whether two-factor authentication is required.

This is useful when you are creating a few accounts and want full control over the data before sending the user their login details.

## Bulk CSV import

A CSV import is the fastest option when onboarding many users. The expected columns are:

- username
- email
- firstname
- lastname
- totp_forced

Example:

```csv
username,email,firstname,lastname,totp_forced
jdoe,jane@example.com,Jane,Doe,false
asmith,alex@example.com,Alex,Smith,true
```

The admin interface validates the file before importing and will report columns or values that are missing or invalid.

## TOTP requirement

You can force a user to set up two-factor authentication during onboarding. This makes account security stronger for sensitive or shared deployments.

Use this when:

- the instance is used by multiple teams;
- employees handle sensitive documentation;
- you want to enforce stronger login protection by default.

## Account management workflow

A practical onboarding flow is:

1. create the initial users in the admin panel;
2. validate their usernames and emails;
3. decide whether they must enable TOTP;
4. share the login instructions or account creation email;
5. assign the user to the right team, workspace, or document permissions afterward.

This separation keeps administration clear: create the account first, then grant the right access scope.

## Permissions after creation

User creation and permission assignment are separate concerns. After the account exists, you still need to decide:

- which team the user belongs to;
- which workspace they can access;
- which category or document they can edit;
- whether they are a viewer, editor, or admin in a given scope.

This is where the collaboration model becomes useful: a user can be invited, assigned, or joined through a temporary access link without over-sharing the entire instance.

## Good practices

- Import users in batches when onboarding a large team.
- Validate the CSV before sending the final import.
- Use TOTP enforcement for administrators or sensitive knowledge areas.
- Assign broad access only when it is truly necessary.
- Keep the admin list small and explicit.

This page is for instance administration. Team and document permissions are configured in the collaboration and workspace flows, not in the global user creation screen.
