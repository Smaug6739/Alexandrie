The administration panel is the place for instance-level operations. It is separate from team or workspace management and is meant for global concerns such as account creation, overview stats, and app-level administrative access.

## Admin access model

Alexandrie distinguishes between:

- regular users;
- workspace or team admins;
- global app administrators.

A workspace admin manages permissions and content inside a specific area of the knowledge base. A global admin has broader instance-level visibility and can manage users and global settings beyond one part of the tree.

## Opening the admin panel

The admin interface is available to users who have app admin rights. From there, you can:

- review overall platform statistics;
- manage users;
- create accounts in bulk;
- check the activity of the instance.

## Granting app admin privileges

To make a user an app administrator, add their user ID to the `ADMIN_ACCOUNTS` environment variable used by the backend.

Example:

```text
ADMIN_ACCOUNTS=123456789012345,234567890123456,345678901234567
```

This value is parsed as a comma-separated list of user IDs. Once the backend refreshes the admin configuration, the selected users receive app admin permissions.

:::warning
If you add a user to `ADMIN_ACCOUNTS`, it may take up to 15 minutes for the change to be visible in the app. In practice, logging out and back in is the quickest way to refresh the current session and see the admin rights appear.
:::

### How to find a user ID

1. Log in as the target user or as an existing admin.
2. Open the user list or profile in the app.
3. Copy the user ID that is shown.
4. Add it to `ADMIN_ACCOUNTS`.
5. Restart or reload the backend configuration where relevant.

## Recommended workflow

For most self-hosted instances, the practical workflow is:

1. create the initial admin account;
2. sign in to the administration dashboard;
3. create or import the rest of the users;
4. add the intended user IDs to `ADMIN_ACCOUNTS`;
5. keep the admin list small and intentional.

This keeps the global admin layer clear and avoids granting broad instance access to people who do not need it.

## What app admins can do

App administrators can manage the instance-level aspects of Alexandrie, including:

- reviewing platform-level stats;
- creating and importing accounts;
- managing user access at a broader level;
- overseeing shared workspaces and team-level operations when necessary.

This is different from a regular workspace owner or team admin, whose scope is limited to a specific part of the knowledge base.

## Keeping the instance controlled

A private Alexandrie instance works best when the admin model stays clear:

- trusted users get global access only when needed;
- workspace permissions remain specific to the team or project;
- account onboarding stays traceable and documented.

This helps maintain a clean separation between instance administration and day-to-day knowledge management.
