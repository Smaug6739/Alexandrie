Alexandrie is designed for knowledge that needs to stay structured, searchable, and collaborative without becoming rigid. The app combines a document hierarchy, a rich Markdown editor, accessible sharing, and media management in one place.

## The main layout

The app is organized around a left sidebar, a content tree, and a document workspace. On the left, you navigate your teams, workspaces, categories, and documents. In the center, you read or edit the current document. On the right side of the editor, you can manage metadata, attachments, and document actions depending on the context.

![overview of the main layout with sidebar, document tree, and editor](/assets/overview-layout.png)

## Teams, workspaces, and documents

Alexandrie separates structure from permission. A team groups people, a workspace defines a content scope, a category organizes material, and a document contains the actual writing.

This means you can create a product wiki, a research notebook, a team handbook, or a project knowledge base without forcing every document into the same model.

## Document editing and publishing

Each document is a Markdown-first workspace. You write in a rich editor, use internal links, add media, and format content using blocks, diagrams, and tables. Documents can also have their own theme, icon, thumbnail, and color to make them easier to recognize at a glance.

![editor](/assets/editor.png)

## Sharing and collaboration

A document or a parent node can be shared with team members using explicit permissions. You can invite users, grant viewer, editor, or admin access, and create temporary invite links for workspace access.

This is especially useful for cross-functional teams, project spaces, or knowledge bases shared across several departments.

![sharing modal](/assets/sharing.png)

## Views and organization strategies

Alexandrie is not limited to a single way of organizing content. You can model a knowledge base in many ways:

- as a documentation tree;
- as a project hub with workspaces and categories;
- as a lightweight wiki with nested notes;
- as an operational board using the Kanban view;
- as a personal knowledge vault with documents stored anywhere in the hierarchy.

The same document can live under a workspace or category, and the hierarchy can evolve without rewriting content.

## Themes and document styling

One of Alexandrie’s strengths is that the style of a document can change without changing the content. You can apply a global reading theme, adjust the available styles, or override a document with a specific theme such as academic, minimal, modern, or LaTeX-inspired.

This makes it easy to switch from a colorful knowledge base to a more sober writing environment, or to give a document a strong visual identity without editing the text itself.

## Files, imports, and backups

Alexandrie handles media as first-class content. You can upload files, attach documents, preview PDFs, images, audio, and video, and maintain a stable archive with export and backup flows.

The import system supports full backups, selected content, and bulk file imports. This matters for migrations, restoration, and moving data between instances without losing structure or metadata.

## Why this matters

The app is built for evolving information, not static silos. You can start with a simple team space and grow into a richer system with nested documentation, project views, permissions, and formatting rules that make reading and navigation easier over time.

That is the core Alexandrie approach: structure should support knowledge, not get in the way of it.
