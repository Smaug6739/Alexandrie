Alexandrie lets you style a knowledge base without changing the actual content. The same note can look very different depending on the theme, document preferences, and metadata assigned to it. This is useful for creating a clean public wiki, a dense technical knowledge base, or a more editorial, polished workspace.

## Document metadata and styling

Every document can be customized in several ways:

- icon or emoji;
- color accent;
- thumbnail image or inline SVG;
- display theme;
- text presentation settings such as font family, size, and line height.

These settings are available from the document metadata modal, which is the place to adjust the visual identity of a node without editing the text itself.

### Icons and colors

A document or workspace can have a dedicated icon and accent color. This is not only cosmetic: it makes large knowledge bases easier to scan and helps each section stand out visually.

Use this to:

- highlight core project spaces;
- group documents by function or domain;
- make a workspace easier to recognize in a sidebar or tree.

### Thumbnails and SVG artwork

You can also assign a custom thumbnail. This is especially valuable for landing pages, team spaces, or document collections where a visual preview helps recognition. For more custom designs, an SVG thumbnail can create a richer visual identity while keeping the document content unchanged.

This is a practical tool for documentation hubs, course pages, or client-facing workspaces.

## Theme system

Themes are a central Alexandrie feature. A theme changes how a document is rendered without requiring you to rewrite the content. It affects the reading experience, not the source text.

Available styles include:

- Alexandrie
- LaTeX
- LaTeX colored
- Modern
- Academic
- Material
- Minimal

This creates a very powerful workflow: write in one consistent format, then choose a presentation style that fits the audience.

### Global vs local themes

You can apply a theme at the global app level or override it per document. That means the same base can switch between different reading modes depending on the context:

- a technical document can use an academic or LaTeX style;
- a project overview can look modern and lighter;
- a private note can use a quieter minimal theme;
- a public-facing page can use a cleaner presentation suited to readers.

The result is that the same content can feel different depending on the purpose of the page.

## Why themes matter

Good knowledge design is not only about structure. It is also about readability. In a large library, different kinds of documents need different emphasis:

- research notes may benefit from a classic academic presentation;
- product documentation may need a clean minimal look;
- internal runbooks may prefer a more functional style;
- landing pages may benefit from a visually stronger modern theme.

With Alexandrie, you can change the look and feel quickly without reworking the actual writing.

## Personal preferences and defaults

The app also allows users to configure default reading preferences in the settings, including:

- document size;
- default font family;
- line height;
- print mode;
- number of headings;
- colored tags;
- thumbnails inheritance.

This makes the reading experience consistent across a workspace while still leaving room for per-document visual overrides.

## Design strategy for knowledge bases

A well-designed Alexandrie instance usually mixes three layers:

1. structural clarity: the tree, workspaces, categories, and documents;
2. content styling: readable Markdown, smart headings, and visual hierarchy;
3. presentation layer: theme selection, icons, colors, and thumbnails.

That combination lets you build a knowledge base that is both useful and easy to browse, without sacrificing authoring speed or maintenance clarity.

In practice, the design system is intentionally flexible: you can keep everything minimal, or give each part of the knowledge base a recognizable identity while keeping the textual content central.
