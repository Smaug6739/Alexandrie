Coolify can deploy Alexandrie from the repository's `docker-compose.yml`. This leaves Coolify responsible for the server, domains, and TLS certificates while Compose keeps the stack definition.

## Create the resource

1. In Coolify, create a **Docker Compose** resource from the Alexandrie repository, or paste `docker-compose.yml`.
2. Add every `.env.example` variable in Coolify and give each secret a unique production value.
3. Assign a domain to the `frontend` service on port `8200`.
4. If the API and files use subdomains, also route `backend:8201` and `rustfs:9000`.
5. Deploy, then open the frontend domain.

## Variables to change

When Coolify terminates HTTPS, set `ALLOW_UNSECURE=false` and use public HTTPS URLs for `FRONTEND_URL`, `API_URL`, and `CDN_URL`. With `wiki`, `api`, and `files` under `example.com`, use `COOKIE_DOMAIN=example.com`.

## Persistence and ports

Keep the MySQL and RustFS volumes declared by Compose. Do not assign domains to `mysql` or unused administration interfaces. Published Compose ports can be removed or replaced with internal ports depending on how Coolify routes the deployment.

::tip
---
title: Test before closing access
---
Verify registration, login, and an image upload through public domains before removing any temporarily exposed port.
::
